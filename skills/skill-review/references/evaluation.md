# 按实际任务验证

只有证据足够时才报告效果提升。测试规模随变动和风险选择，不预设通用及格线或无限迭代。

## 格式与行为分开

- **格式检查**：入口可解析、名称与宿主要求一致、引用可用、依赖描述准确。
- **行为检查**：真实任务是否完成，是否保留用户约束、避免无效步骤并给出可靠证据。
- **宿主触发**：宿主是否发现并实际选择技能。手动指定技能的测试不证明自动调用能力。
- **接受情况**：用户反馈或实际使用结果。自审和模拟走查不能代替用户验收。

## 效果比较

选择具有代表性的真实任务及失败边界，在观察输出前确定验收标准。同一任务比较用技能/不用技能，或新版/旧版；保持模型、工具、数据和授权范围尽量一致，并记录无法控制的差异。

使用隔离上下文和工作副本，避免一组拿到另一组结论、共享写冲突或测试污染当前产物。若环境允许且已有相应授权，可用独立执行者；否则串行隔离或请用户评审。不能把同一作者模拟两种答案称为独立对照实验。

先比较是否合格，再比较耗时、工具调用、必要人工干预与实际 Token 记录。多次采样可暴露波动，样本很小时列原始结果，不把偶然领先包装成稳定排名。收集全部尝试及失败原因；仅在合格样本上比较效率时，同时报告两组总体通过率，避免掩盖失败成本。

输出可简短列出：任务与条件、预先约定的标准、实际结果和证据、观察到的差异、未控制因素。主观写作或设计质量可做隐藏版本身份的评审，但结论仍受任务与评审者影响。

## 触发与误触发

只有宿主支持自动选择且能观察真实调用时，才测自动触发；不能观察则记未测或不可观测。

构造应调用的正例、不应调用的邻近反例，以及需要按上下文判断的边界请求。改写措辞，避免所有题都点名技能。若显式调用，单独记为入口验证。

| 指标 | 口径 |
| --- | --- |
| 召回率 | TP / (TP + FN)：应调用的请求中实际调用的比例 |
| 精确率 | TP / (TP + FP)：实际调用中应调用的比例 |
| 误触发率 | FP / (FP + TN)：不应调用的请求中被调用的比例 |

TP 为应调且调用，FN 为应调未调，FP 为不应调却调用，TN 为不应调且未调用。保留原始计数；分母为零时写不适用，不用零分或满分代替。边界题若无明确预期，单列观察而不强塞入计分。

改简介时用开发样本调整，另留未用于改写和选版的测试样本。多候选或多轮优化需要独立验证集用于选版，最终测试集只作最终评估；一旦用它挑版本或反复修改，它就不再是未见测试集，需要新样本才能评价泛化。

## 成本与停止条件

指标先定口径再采集。看不到 Token 统计就写未测；文件字符或字节数只能作为加载体积，不能换算成实际消耗。任务“无需用户改动即可接受”的比例只有真实接受记录才可计算，作者自评另记。

不存在所有技能都必须达到的统一触发率、接受率或自治等级。是否需要人工参与由任务授权和风险决定；需要确认的工作流不因此低人一等。

按本轮验收范围和预算设停止条件：约定目标达到即可收口；遇到外部阻塞或测试条件不足，保留未证项并说明。根据共性问题迭代，不为凑分堆规则，不因反馈尚未收齐无限重跑。
