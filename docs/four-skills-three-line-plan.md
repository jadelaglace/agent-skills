## 7. 本机主线：回到信任模型、抓住少量不变量

以恢复树为起点，不继承融合版内容作为默认底稿。先恢复，再按两个条件筛选亮点：它能防住实质失误；又能用短小的通用原则表达，不绑定特定模型、工具或项目。

建议首轮仅考虑这些原则，不设必须吸收数量：

1. 主张的完成程度不能超过证据；实际用户结果不能被工程绿灯替代（基线已有则零修改）。
2. 数据有明确权威和允许写入者；派生可重建，别把技术实现写死（已有则零修改）。
3. 外部依赖和长生命周期操作有明确失败、取消、清理边界（已有则零修改）。
4. 设计验收看实际输出；保留要求中的主体特征和内容，诊断加工不能代替原始交付验收（只在基线有缺口时补一句）。
5. 验证条件会改变结果时，检查相关实际路径并限定结论；不为所有任务强制全环境矩阵。
6. 变更涉及协议或关键链路时，验证受影响的真实路径；不把所有小改动升级为全产品 E2E。

不直接恢复这些 1028 式细则：全局固定文档编号/两区、全局前缀、每轮固定数量表、统一图像平台、强制每个任务完整走四层、所有函数镜像测试、纯数量驱动的退役补测、每回合 bump/commit。

入口保留目标、职责、关键边界与按需路由。只有能明显改变行为的专项内容才进入 reference，普通模型常识不用加一大套清单。保留“必要时记录当前工作”，但不要求 Codex Goal 或名为 Active Task 的特定对象。
